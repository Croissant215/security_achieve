# 창 없는 실행과 재시작 검증

2026-10-07, Windows / Python 3.12.10 / Microsoft Edge.

## 변경 개요

서버 재시작마다 서명 키가 바뀌어 저장한 글의 소유자 세션이 끊겼다. 키를 기존 SQLite의 settings에 최초 한 번 저장하고, 브라우저 쿠키를 마지막 사용 후 30일간 유지하도록 변경했다. start.vbs와 stop.vbs는 pythonw를 호출한다. 실행 도우미는 파일 잠금으로 중복 서버를 막고 종료 요청 파일을 확인해 서버를 닫는다.

## 검증 결과

- 서버 회귀 검사 9개 통과: 재시작 후 같은 쿠키로 목록·본문·로그인 유지, 다른 쿠키의 글 접근 거부, 초기화 후 삭제 확인 포함.
- test_launcher.py 통과: 실제 pythonw 서버 시작, 중복 실행, 종료, 이미 종료된 상태의 종료 요청, 재시작 후 글과 로그인 유지, 사용 중인 포트의 오류 처리. 한글·공백이 있는 임시 데이터 경로를 사용했다.
- test_browser.py와 test_board_browser.py 통과: SQL 6개·XSS 6개, 게시판 사용 동선, iframe 격리, 오류·시간 초과, 초기화, 모바일 레이아웃.
- 임시 DB·포트로 검증했다. 실행 중인 사용자 서버와 실제 실습 DB는 건드리지 않았다.
- VBS의 경로 인용과 창 숨김 인자를 코드에서 확인했다. 브라우저 자동 열기와 종료 안내 창은 사용자 작업을 방해하지 않도록 자동 검사에서 생략했다.

## 리뷰

- 범위: app.py, launcher.pyw, 시작·종료 VBS, 테스트, README. 위험 수준: 중간(세션 유지 정책 변경).
- 코드 품질·정확성: 기존 DB에 settings만 추가한다. 잠금은 프로세스 종료 시 운영체제가 해제한다. 실행 상태 JSON은 임시 파일을 만든 뒤 교체한다. 시작 직후의 종료 요청을 오래된 파일로 삭제하지 않도록 생성 시각을 비교한다.
- 보안: 서버는 127.0.0.1에 바인딩한다. 종료 HTTP API나 PID 기반 강제 종료를 추가하지 않았다. 키·DB·로그는 Git에서 제외되는 instance에 저장한다. 쿠키의 HttpOnly/SameSite와 기존 CSRF·소유자 검사를 유지한다.
- 성능: 0.25초 간격으로 종료 요청을 확인하며 HTTP 요청은 기존 Werkzeug의 스레드 서버로 처리한다. 종료 시 처리 중인 요청을 기다린다.
- 배포·문서: 추가 패키지가 없다. 기존 콘솔 실행은 유지한다. README에 설치, 시작·종료, 세션 유지 기간, 초기화·복구 범위를 명시하고 no-ai-slop/eval.md로 문구를 검토했다.
- 이번 변경의 Critical/Major 발견 사항: 없음. Minor 제한: VBS 실행이 차단된 PC는 README의 직접 실행이 필요하다. 전체 프로젝트의 기존 후속 과제(글 저장·학습 기록의 트랜잭션, 학습 SQL의 비밀번호 보관)는 이번 범위에 포함하지 않았다.
- 결론: APPROVE. 로컬 교육 도구의 재시작과 실행 편의 개선 범위로 반영한다.

## 검사 중 수정

첫 도우미 검사에서 프로세스 실행 직후 아직 생성되지 않은 로그를 assertion 메시지 인자로 읽어 FileNotFoundError가 발생했다. 프로세스 종료 여부와 관계없이 인자를 먼저 평가한 것이 원인이다. 자식 프로세스가 종료된 경우에만 로그를 읽도록 바꾸었고 재검사에 통과했다.

## 데이터 유지 범위

같은 브라우저 프로필의 쿠키가 남아 있어야 이전 글을 볼 수 있다. 쿠키 삭제·만료 또는 변경 전 이미 끊긴 세션의 글은 자동 복구하지 않는다. 공용 PC에서는 로그아웃하며, 글과 학습 기록까지 삭제하려면 실습 초기화를 사용한다.
