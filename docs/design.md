# 초기 화면 설계

## 첫 사용 안내 개선

- 첫 화면에서 정상 로그인부터 시작한다. 로그인 → 글 작성 → 글 열고 비교 순서를 표시하되 자유롭게 다른 화면으로 이동할 수 있다.
- 로그아웃 상태는 로그인, 로그인 후 빈 목록은 첫 글 작성, 글이 있는 목록은 최근 글 열기를 다음 행동으로 안내한다.
- 계정·본문 예제 버튼은 입력칸과 적용 모드만 변경한다. 로그인·저장은 사용자가 실행 버튼을 눌러 요청한다. 글 예제가 기존 입력을 바꾼다는 설명을 버튼 옆에 둔다.
- 학습 패널은 결과를 먼저 보여주고 코드·SQL은 접어 둔다. 모바일에는 결과 위치로 이동하는 링크와 키보드 초점 이동을 제공한다.
- 판정 로직, 오류·시간 초과, 관찰 한계, 삭제 범위를 유지한다. 디자인 검색의 건너뛰기 가능한 안내 원칙과 shadcn 안내 제목·설명 구조를 참고했다.

## 게시판과 학습 패널 · 2026-10-05

- 기존 녹색·회색 토큰과 기본 글꼴을 유지한다. shadcn `table-demo`의 caption, thead, tbody 구조를 네이티브 HTML에 적용했다.
- 첫 화면은 `/board`다. 로그인 → `/board/new` 작성 → 저장 후 목록 → 제목 링크 → 상세 본문 순서다.
- 목록은 제목과 작성 정보 두 열로 표시한다. 작은 화면에서도 작성자와 시간대를 포함한 시각을 줄바꿈해 표시한다.
- 빈 목록, 입력 오류, 저장 실패 시 내용 보존, 저장 중 버튼, 저장 완료 안내, 없는 글의 404 상태를 제공한다.
- 작성자는 게시판 로그인 결과로 정한다. 로그인 화면에서 같은 입력으로 두 SQL 구현을 실행하되 선택한 모드의 결과만 게시판 인증에 반영한다.
- 상세의 본문은 sandbox iframe에서 출력한다. 같은 원문을 취약·방어 방식으로 비교할 수 있다. 제목·목록·학습 패널·원문 보기는 항상 이스케이프한다.
- 넓은 화면은 게시판 왼쪽, 학습 패널 오른쪽이다. 1000px 이하에서는 학습 패널을 아래로 이동하며 details로 접을 수 있다.
- 패널은 최근 서버 요청 1건의 입력·실행 함수·결과를 표시한다. 본문 요청 대기, 관찰 신호, 오류, 6초 시간 초과를 구분한다. 실행된 함수는 녹색 테두리로 강조한다.
- shadcn accordion 예제의 접기 동작을 네이티브 details로 구현한다. 기존 제품에 맞춰 녹색 토큰을 유지하며 디자인 검색의 아동용 글꼴·입체 장식은 적용하지 않는다.
- 실제 Edge에서 목록의 1440px·375px 스크린샷을 확인했고, 작성·열람 및 모바일 가로 넘침 검사를 통과했다.

## 실습 화면

기준: 2026-09-30 요구사항 명세서 v0.2. 학생이 입력을 준비하고, 취약 구현을 실행한 뒤, 방어를 적용해 같은 입력으로 비교한다.

- 계층: 실습 선택 → 목표 → 입력 → 두 결과 → 실제 코드 → 전체 검증표 → 접힌 로그.
- 밝은 회색 바탕, 흰 실습 영역, 짙은 녹색 실행 버튼. 취약 결과의 강조는 갈색과 상태 텍스트를 함께 사용한다.
- UI/UX Pro Max의 데이터 도구·접근성 지침과 shadcn의 버튼, 탭, 표 패턴을 참고한다. 선택 상태, focus-visible, border/background/foreground/muted 토큰을 적용한다.
- Flask + HTML 구성에 맞춰 네이티브 button, nav, details, dialog, table을 사용한다. React 런타임은 추가하지 않는다.
- 예제나 관제 수치를 꾸며내지 않는다. 실행 전, 실행 중, 오류, 입력 변경, 성공, 실패 상태를 각각 표시한다.
- 760px 이하는 메뉴를 상단으로 이동하고 결과·코드를 세로로 쌓는다. 긴 코드는 줄바꿈, 표는 내부 스크롤을 제공한다.
- 키보드 초점 표시, 명시적 입력 레이블, 상태의 텍스트 설명, 44px 이상 조작 영역, reduced-motion을 유지한다.
- 합격 기준: SQL 6개·XSS 6개 브라우저 검증, 초기화 및 다시 실행, 375/768/1024/1440px에서 페이지 가로 넘침 없음, 외부 CDN 요청 없음.
