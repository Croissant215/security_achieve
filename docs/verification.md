## 코드 리뷰 개요

- 변경 유형: 신규 기능. 초기 구현의 검토 범위는 로컬 학습 도구이다.
- 위험 수준: 중간. SQL·HTML 취약 처리를 의도적으로 포함하며, 메모리 DB와 브라우저 격리 영역에 한정한다.
- 대상: `app.py`, `static/`, `templates/`, 테스트·실행 문서.

### 주요 작업

기존 관제 훈련장 대신 명세서 v0.2의 로그인·게시판 비교 흐름을 구현했다. 같은 입력과 실제 실행을 유지하기 위해 코드 생성 없이 함수 경로를 전환하고, 출력 코드도 실행 함수에서 읽는다. SQLite의 실행 데이터와 실제 브라우저 관찰을 연결한다.

### 네 가지 검토 관점

- **코드 품질:** Flask 앱 생성 함수로 테스트 DB를 분리했다. 네이티브 HTML과 JavaScript를 사용하며 프런트엔드 빌드 도구가 필요 없다. 입력 검증과 공통 오류 처리를 둔다.
- **보안:** 의도한 SQL 취약 경로는 새 메모리 DB와 가상 계정만 사용한다. 쓰기 금지·허용 함수 제한·쿼리 실행량 제한을 둔다. XSS는 동일한 sandbox/CSP 아래에서 비교한다. 주 화면은 입력을 HTML로 삽입하지 않는다. POST에는 세션별 실습 토큰이 필요하다.
- **성능:** 작은 로컬 실습 데이터, 최대 4,000자 게시글, 최근 100건 화면 로그, SQL 비밀번호 검사 횟수 제한. 임의 JavaScript의 CPU 사용량 제한은 미지원이며 README에 명시했다.
- **저장소·배포:** 실행 버전 고정, 가상환경·DB·스크린샷 제외, 설치·시연·출처 문서 제공. 학교 PC와 다른 Python 버전에서는 추가 확인이 필요하다.

### Critical

현재 검사 범위에서 미해결 차단 항목 없음. 의도적으로 취약한 학습 경로를 일반 서비스용 코드로 사용하면 안 된다.

### Major

현재 검사 범위에서 미해결 항목 없음. 원문 HTML의 출력은 격리된 게시글 템플릿 한 곳에만 허용했다.

### Minor / 후속 확인

- 학교 PC 설치 및 실제 발표 화면 크기 확인.
- 프로젝트 공개 라이선스 선택, 제출 커밋·태그, PPT와 녹화 자료 준비.
- 사용자 지정 지연 스크립트·무한 루프는 검증 범위 밖이다. 전용 코드 분석기나 악성 코드 분석 샌드박스가 아니다.
- 이번 검증에는 외부 취약점 DB 기반 의존성 감사 도구와 전체 접근성 감사 도구를 포함하지 않았다.

### 유지할 구현

두 모드의 같은 입력·동일한 환경, 오류와 차단의 구분, XSS의 실제 실행 양성 대조군, 테스트 데이터 격리를 유지한다.

### 결론

**APPROVE — 초기 로컬 실습 버전.** 기본 실습 흐름과 명세서의 6종 사례를 재현했다. 최종 학교 제출 완료를 뜻하지 않으며, 외부 배포 승인이 아니다.
