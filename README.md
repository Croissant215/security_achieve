# Security Lab · 웹 취약점 비교 실습

학생을 위한 로컬 웹 보안 학습 도구입니다. 로그인에서 **SQL 인젝션**, 게시판에서 **저장형 XSS**를 직접 실행하고 같은 입력에 대한 취약·방어 코드의 결과를 비교합니다.

기준 문서: 「20602 김가온 요구사항 명세서」, 2026-09-30 초안 v0.2. 초기 버전 **0.1**.

## 실행

- Windows, **Python 3.10 이상**. 검증 환경: Python 3.12.10, Microsoft Edge.
- 처음 설치할 때는 인터넷이 필요합니다. 설치 후 핵심 실습은 오프라인으로 작동합니다.
- 외부 CDN, Node.js, 별도 DB 서버는 필요하지 않습니다.

프로젝트 폴더에서 **`run.bat`을 더블 클릭**한 다음 브라우저로 **http://127.0.0.1:5000**을 엽니다. 처음에는 `.venv` 생성과 패키지 설치가 진행됩니다. 종료는 실행 창에서 `Ctrl+C`입니다.

PowerShell에서 직접 실행하는 방법:

```powershell
cd C:\Users\psych\Documents\achieve
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

다른 PC에서는 내려받은 프로젝트 폴더 경로로 `cd`를 바꾸세요. 가상환경 활성화 명령은 필요하지 않습니다.

## 실습 순서

### 게시판 기본 동작

처음 사용할 때는 화면의 안내 버튼을 순서대로 누르세요.

1. **1단계 · 로그인하러 가기 → 정상 계정 입력 → 로그인**
2. **2단계 · 첫 글 작성하기 → 일반 글 예제 입력 → 글 저장**
3. **최근 글 열기**로 저장한 본문 확인
4. 새 글에서 **XSS 예제 입력 → 글 저장 → 최근 글 열기 → 같은 글 두 모드 비교**

예제 버튼은 입력칸만 채웁니다. 결과를 확인한 뒤 **실행 코드 보기**를 펼치면 처리에 사용한 코드를 읽을 수 있습니다. 휴대폰 화면에서는 **결과 설명 보기**로 아래 학습 패널에 이동합니다.

첫 화면에서 **로그인 → 글쓰기 → 글 저장 → 목록의 제목 클릭** 순서로 이용합니다. 작성자는 로그인한 가상 계정이며, 제목·본문·작성 시각을 SQLite에 저장합니다. 옆 학습 패널에는 최근 요청에서 실행한 함수와 입력·처리 결과가 표시됩니다. 작은 화면에서는 패널이 아래에 나타납니다.

로그인 화면의 **같은 입력으로 두 모드 비교**는 같은 아이디·비밀번호를 두 구현에서 실행합니다. 선택한 코드의 결과로 로그인하며 다른 모드의 결과는 패널에만 표시합니다. 예를 들어 `admin' -- / wrong`은 취약 코드에서 admin으로 로그인되고 방어 코드에서는 거부됩니다.

게시글 본문에 `<script>labSignal()</script>`를 저장하고 목록에서 글을 연 뒤 **같은 글 두 모드 비교**를 누릅니다. 취약 본문에는 실행 신호가, 방어 본문에는 원문이 글자로 표시됩니다. 본문 출력 모드를 바꿔도 게시판 로그인 상태는 바뀌지 않습니다.

학습 패널은 완료된 서버 요청과 브라우저 관찰을 보여줍니다. 함수 내부를 한 줄씩 실행하는 디버거는 아닙니다. 서버 기록은 브라우저 세션별 최근 1건만 보관하며 다음 로그인·저장·열람·로그아웃 요청에서 갱신합니다.

### 보안 실습

상단 **전체 검증·초기화**(`/lab`)에서 기존 사례별 검증을 실행합니다. 이 화면의 모드별 로그인 실험과 게시판 로그인은 별도로 관리하며, 실습 초기화는 둘 다 삭제합니다.

1. **SQL 인젝션**에서 ‘정상 계정’을 불러와 취약 코드를 실행합니다. 가상 회원 페이지를 열어 실제 로그인 상태를 확인합니다.
2. ‘로그인 우회’를 불러와 실행합니다. `admin' --` 입력으로 비밀번호 조건이 주석이 되는 것을 확인합니다.
3. **방어 적용 → 같은 입력으로 재실행**을 누릅니다. 매개변수 바인딩으로 로그인 결과가 바뀝니다. 입력을 편집하면 이전 결과와 조건이 달라졌다는 안내가 표시됩니다.
4. **전체 검증 실행**으로 정상 계정, 잘못된 비밀번호, 우회 입력을 두 모드에서 비교합니다.
5. **저장형 XSS**에서 ‘실습용 스크립트’를 실행합니다. 게시글은 SQLite에 저장된 뒤 다시 조회되고, 격리된 iframe에서 열립니다.
6. 취약 결과의 `[스크립트 실행됨]`을 확인하고 방어를 적용해 재실행합니다. 방어 결과에는 입력한 코드 자체가 글자로 보입니다.
7. XSS 전체 검증표에서 일반 글, HTML 포함 글, 스크립트 예제의 6개 결과를 확인합니다.
8. **실습 초기화**로 이 브라우저의 게시글·로그인·화면 결과·로그를 지우고 재시연합니다.

가상 계정: `student / study1234`, `admin / admin1234`. 실습 비밀번호는 화면과 실행 쿼리에 보일 수 있습니다. 실제 계정이나 비밀번호를 사용하지 마세요.

## 구현과 관찰 기준

| 기능 | 구현 |
|---|---|
| 로그인 | 각 실행마다 같은 가상 계정을 가진 메모리 SQLite 생성. 비밀번호는 scrypt 해시 비교 |
| SQL 인젝션 | 취약 경로의 문자열 결합, 방어 경로의 `?` 바인딩을 실제 실행 |
| 회원 페이지 | 모드별 서버 세션의 인증 결과 확인. 실패·초기화 후 접근 거부 |
| 게시판 | 제목·본문 작성 → 목록 → 상세 열람. 현재 브라우저의 글만 표시 |
| 저장형 XSS | 모드별 게시글 원문 저장 → 재조회 → 원문 출력 또는 `html.escape` 출력 |
| XSS 실행 | 두 모드에 같은 iframe sandbox/CSP 적용. `labSignal()` 또는 `alert()` 실행 신호를 관찰 |
| 결과·로그 | 실제 서버 처리 결과와 브라우저 관찰. 주 화면에는 `textContent`로 안전하게 출력 |
| 코드 비교 | `inspect.getsource`로 현재 실행 함수의 소스 제공 |
| 전체 검증 | 실습당 3종 × 2모드. 정상/실패/오류를 구분. XSS 방어는 취약 모드 실행 확인과 텍스트 표시를 함께 검증 |

‘통과’는 기대한 실험 결과와 일치한다는 뜻입니다. 취약 모드의 우회 성공이 통과여도 보안상 안전하다는 의미는 아닙니다. 오류·시간 초과는 방어 성공으로 처리하지 않습니다.

## 검증 실행

서버 검사에는 실행 의존성만 필요합니다. 기존 실습 DB를 건드리지 않고 임시 DB를 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_app
```

브라우저 검사에는 Microsoft Edge와 개발용 패키지가 필요합니다. 검사 서버는 임시 포트에서 시작·종료됩니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe test_browser.py
.\.venv\Scripts\python.exe test_board_browser.py
```

스크린샷은 `artifacts/`에 생성합니다. 검사 결과는 [검증 기록](docs/verification.md)을 참고하세요.

## 알려진 범위와 한계

- 서버는 `127.0.0.1`에만 바인딩합니다. 취약 구현이 포함된 교육 도구이며 외부 공개 배포 대상이 아닙니다.
- XSS 신호는 기본 예제의 실행을 관찰하는 장치입니다. 임의의 모든 JavaScript를 분석하는 탐지기가 아닙니다. 150ms 관찰 뒤 지연 실행되는 코드나 실습 함수를 호출하지 않는 코드는 자동 성공 판정 대상이 아닙니다.
- 격리 영역은 DOM 접근·외부 자원·팝업·폼 전송을 제한하지만 브라우저의 CPU 사용량까지 격리하지는 않습니다. 무한 루프와 같은 코드는 실행하지 마세요.
- 각 게시글 미리보기 URL에는 무작위 접근 식별자가 들어갑니다. 로컬 실습 데이터용이며 실제 비밀 자료를 저장하는 기능이 아닙니다.
- 화면 로그는 최근 100건이며 브라우저 새로고침 시 사라집니다. 서버 재시작 시 로그인 세션은 무효화됩니다. 게시글 DB는 유지되지만 이전 세션의 글을 찾는 목록·검색 기능은 초기 범위에 없습니다.
- 사용자별 초기화는 현재 브라우저 실습만 삭제합니다. 전체 로컬 DB를 새로 만들려면 서버 종료 후 `instance/lab.sqlite3` 파일을 삭제하고 다시 실행합니다.
- 학교 PC에서의 설치·시연, PPT, 녹화 영상, 최종 제출 태그는 후속 작업입니다. CSRF·IDOR·SIEM·아카이브는 이번 초기 버전에 포함하지 않습니다.

## 문제 해결

- **python을 찾을 수 없음:** Python 3.10 이상을 설치하고 새 터미널에서 `python --version`을 확인합니다. 필요하면 명령의 `python`을 `py -3`으로 바꿉니다.
- **ModuleNotFoundError:** `.venv`의 Python으로 실행했는지 확인하고 `-m pip install -r requirements.txt`를 다시 실행합니다.
- **5000 포트 사용 중:** 이미 실행 중인 실습 창을 확인하고 하나만 실행합니다.
- **403 또는 세션 오류:** 서버 재시작 후에는 실습 페이지를 새로고침합니다. `localhost`와 `127.0.0.1`을 섞어 사용하지 않습니다.
- **XSS 판정 불가:** 기본 예제로 다시 시도하고 요청·처리 로그를 확인합니다. 시간 초과나 오류를 차단 성공으로 해석하지 않습니다.
